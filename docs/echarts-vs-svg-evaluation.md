# ECharts versus SVG

## Decision scope

This is a comparison of the experimental ECharts lab against the stable SVG
dashboard. It is not an authorization to replace the stable implementation.

| Criterion | Stable SVG | ECharts lab | Current assessment |
|---|---|---|---|
| Static GitHub Pages | Works | Works with local bundle | Tie |
| External runtime dependency | None | None after local bundling | Tie |
| Historical comparison | One stable view | Two entities and six series | ECharts advantage |
| Data transformation | Application code | ECharts dataset transforms | ECharts advantage for experimentation |
| Accessibility | Native labels and stable DOM | ARIA generated by ECharts plus native controls | Requires manual review |
| Responsive behavior | Covered by stable dashboard QA | Covered by six E2E scenarios | Tie pending visual review |
| Bundle cost | No chart engine bundle | Local ECharts bundle under 1.5 MB transferred | SVG advantage |
| Interaction potential | Intentionally limited | Tooltip, legend scroll and data zoom | ECharts advantage |
| Maintenance risk | Low and known | New dependency and option contracts | SVG advantage |
| Production readiness | Existing baseline | Experimental branch only | SVG remains default |

## Evidence available

- ECharts browser scenarios: `6 passed`.
- Python contracts: `29 passed`.
- Local bundle: no CDN request detected.
- Local bundle: below the `1.5 MB` transfer threshold.
- Stable dashboard: unchanged by this experiment.

## Decision rule

Promote ECharts only if the visual review confirms that its additional
comparison and interaction value justifies the bundle and maintenance cost.
Otherwise, retain SVG as the production renderer and keep the ECharts lab as
an archived technical experiment.

## Remaining gates

1. Review the lab and stable dashboard side by side at desktop and mobile
   widths.
2. Record findings for readability, chart interpretation, contrast and
   interaction density.
3. Choose one outcome: promote, keep experimental, or remove the branch.
4. If promoted, create a separate integration change and rerun all stable
   QA, smoke and Pages checks.
